zeugnis — burndown

Has this cleanup converged?

A zeugnis cycle has converged when every finding it opened is closed and the latest pass had nothing left to close; it has stalled when a pass closes nothing while findings are still open. The exact counts for this run are filled in from the ledger below.

Escalated is not a worse kind of open. It is a finding zeugnis reopened past its thrash limit and refused to retry — the cycle gave up and handed it back to a human, and it will never close on its own.

  • ✓closed — fixed and re-verified; needs nothing
  • ●open — still queued for a later pass
  • ▲escalated — a human must act; the cycle stopped retrying
  • ╱cumulative closed — the trend line, findings closed so far
Click a "by status" or "by domain" bar, or focus it and press Enter, to list the findings behind that count.

Did the new tests kill what survived?

A mutant counts as killed only when a real mutation tool saw a test fail on it, or when a new test was proven to pass on the original code and to fail with that mutant applied. The modules and their scores are filled in from analysis/zeugnis/mutation_harden_summary.json below.

Untested mutants sit in code no selected test reaches. They are kept out of the score, so a module can read 100 % while most of it is never exercised: read the untested count before the score.

  • ○before — killed ÷ (killed + survived) with the original tests
  • ●after — the same ratio with the proven new tests
  • ◌untested — counted beside the score, never inside it; amber while any remain
